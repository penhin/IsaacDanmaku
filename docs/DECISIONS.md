# IsaacDanmaku 重要设计决策

> 最后更新：2026-08-11

## D-001：聚焦《以撒》局内陪伴

- 状态：已接受
- 决策：产品只服务 Windows Steam 版 Repentance+ 单机玩法。

## D-002：采用纯 Workshop Mod 与原生事件回调

- 状态：已接受
- 决策：事件、状态、规则、设置与渲染全部在 Lua Mod 内完成。
- 原因：原生回调能提供确定的游戏事实，且用户只需订阅 Workshop 即可使用。
- 后果：核心运行时不引入桌面端、截图、网络、数据库或外部进程。

## D-003：原子事实与产品场景分层

- 状态：已接受
- 决策：回调只生成事实；`RunContext`归并状态；`ScenarioDetector`产生稳定 A1–I9 ID。
- 后果：共享事实只播一条弹幕，场景 ID 发布后不得复用。

## D-004：规则 schema v2 随 Mod 内置

- 状态：已接受
- 决策：规则按场景 ID 触发并随 Workshop 更新，不兼容旧 EventKind/CommentPack ZIP。
- 原因：旧格式尚未形成值得维护的公开生态，单一运行格式更简单可靠。

## D-005：配置菜单是可选集成

- 状态：已接受
- 决策：检测全局`ModConfigMenu`后注册配置；缺失时使用默认值，设置由 IsaacDanmaku SaveData 保存。
- 后果：不要求用户订阅第二个 Mod，也不借用其字体资源。

## D-006：即时弹幕保持本地确定性

- 状态：已接受
- 决策：模型不得进入即时`reflex`链；当前版本不启用`--luadebug`或外部通信。
- 后果：未来运行时模型必须作为新的可选产品组件另行评审，不能破坏纯 Mod 基线。
