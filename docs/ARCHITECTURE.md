# IsaacDanmaku 系统架构

> 状态：持续维护  
> 最后更新：2026-08-11

## 产品边界

IsaacDanmaku 只支持 Windows Steam 版 Repentance+ 单机玩法。运行时完全位于游戏 Lua Mod 内，不需要
Python、WebView、Sidecar、截图、数据库或网络权限。

```text
游戏原生回调
  → Callback Adapter（原子事实）
  → RunContext（本局/楼层/房间状态）
  → ScenarioDetector（A1–I9）
  → CommentEngine（规则、冷却、去重）
  → Danmaku（游戏内 UTF-8 渲染）
```

## 当前数据流

1. `main.lua`加载设置、规则和各运行模块并注册回调。
2. 回调适配器把游戏对象立即转换为普通 Lua 表，不把 Isaac 对象传入领域层。
3. `RunContext`先记录事实；`ScenarioDetector`至多返回一个可评论场景。
4. `CommentEngine`按人格、剧透、频率、冷却和次数选择稳定文案。
5. `Danmaku`在最多四条轨道中从右向左渲染，队列过载时优先保留高优先级消息。
6. 配置由 Mod `SaveData`以带版本号 JSON 保存；损坏或旧版本数据恢复默认值。

由于游戏在换层时先调用`MC_POST_NEW_ROOM`、再调用`MC_POST_NEW_LEVEL`，回调适配器会把这组通知
归一化为“换层 → 静默同步初始房间”，避免用旧楼层上下文判断房间或连续显示两条弹幕。

开发时执行`luamod isaac_danmaku`不会重放原生开局回调。因此入口检测到局内帧后，会静默采集
种子、楼层和当前房间以重建 RunContext，不生成 H1/H2/F1 弹幕，也不污染规则计数。

`F1/H3`和`C8/H5`分别共享换层与死亡事实。生命周期 ID 会记录在场景结果中，但只允许
`F1`或`C8`产生一条即时弹幕。

## 已实现场景

首版实现 `A1、A3、A9、C1、C8、F1–F7、H1–H3、H5、H6`。其中 `H3/H5`是共享事实的
生命周期标记，不是第二条文案触发。

## 安全与失败行为

- 不读取或保存画面，不联网，不访问任意文件；
- 不使用`--luadebug`，不加载 DLL，不依赖 REPENTOGON；
- 配置菜单缺失或异常不阻止核心 Mod 运行；
- 无规则、频率关闭或冷却未结束时保持沉默；
- 字体加载失败时写入游戏日志，不执行外部回退；
- 在线模式要求关闭 Mod，因此不在支持范围内。

## 演进顺序

1. M1：连续受伤、大量掉血、低血生存、快速/超时清房、连续无伤和 Boss 无伤；
2. K：随 Mod 发布的版本化道具与构筑知识；
3. H：通过 SaveData 保存有限、可解释的跨局统计；
4. L：完整地图与路线推断，保持后置。

外部模型不进入即时`reflex`链。若未来恢复运行时模型，必须作为明确的额外安装组件重新设计；
当前 Mod 不预留不安全的 socket、文件信箱或`--luadebug`路径。
