# IsaacDanmaku 目标事件目录

> 状态：M0首版已实现，其余规划中  
> 最后更新：2026-08-11  
> 规模：9类、91个目标场景

本文是 IsaacDanmaku 准备支持的完整可评论场景目录。`A1`至`I9`是稳定的产品场景ID，不等同于底层
回调。Lua回调层只报告客观事实，`RunContext`归并状态，`Scenario`层再产生本目录中的场景。

```text
Mod回调 → 原子事实 → RunContext → Scenario(A1–I9) → CommentEngine
```

## 1. 实现分层

| 层级 | 含义 | 典型场景 |
|---|---|---|
| M0 | 可由Mod回调或当前游戏状态直接确认 | 新局、换层、受伤、死亡、进入房间 |
| M1 | 需要跨帧、跨房间计时或状态比较 | 连续受伤、快速清房、战斗过久、连续无伤 |
| K | 需要版本化离线知识与构筑规则 | 高价值道具、关键协同、冲突组合、低收益购买 |
| H | 需要跨局玩家摘要 | 重复死于同一Boss、个人纪录、习惯和局内梗 |
| L | 需要完整地图、路径或复杂行为推断 | 错过重要房间、路线选择、错过可交互目标 |

层级描述依赖，不表示产品优先级；一个场景可以同时依赖多个层级。

## 11. 重叠场景与触发规则

- `C8`与`H5`共享同一个死亡原子事实：`C8`负责即时反应，`H5`负责本局生命周期结束，不能重复发两条弹幕。
- `F1`与`H3`共享同一个换层原子事实：`F1`描述楼层环境，`H3`维护生命周期。
- `A3`与Boss房进入事实关联；`A4`必须结合本局或历史Boss记录推导。
- 同一时刻命中多个场景时，先聚合事实，再按关键性、具体性、冷却和最近去重只选择一条即时弹幕。
- 事件检测、场景判断与文案选择分别测试；“检测到了”不等于“必须说话”。

```text
A1 A3 A9

```

`F1/H3`与`C8/H5`分别共享一个原子事实，只生成一条即时弹幕。下一阶段优先实现A7、A8、C2、
C3、C4、C5、C6、C9和C10等M1状态机推导；道具知识、完整路线和跨局个性化按K、L、H能力逐步加入。

## 13. 维护规则

- 场景ID一经进入公开内容包不得复用；废弃时保留ID并标记状态。
- 新增场景必须说明所需原子事实、状态窗口、互斥/合并关系和验收用例。
- 文案示例不是检测定义；检测条件不得从文案反推。
- 代码只实现已具备可靠事实来源和测试数据的场景，规划项不得标记为已实现。
